# Desk v0.10.0

Graphs in Desk, complete on the ADR-0011 line: a graph can be authored through the assistant and written on your word, and rehearsed with facts you supply while nothing is kept. The pinned Runtime moves to v0.28.0 and the pinned Runner to v0.7.0, each carrying the fixes of a cross-vendor audit of its own; the Gateway stays at v0.10.1.

**Updating from v0.9.0 needs no backup step:** nothing here changes a desk's `jpack.json`, a Jobs store, a lock or a signing key without your confirmation on the page. The new Runner refuses an input profile whose trusted receipt key is not a point on the curve; such a key was never a Gateway's, so a profile made through Desk is unaffected.

## What changes for you

- **Author a graph** (Project → Graphs → New, or an existing graph → Edit). The assistant's graph purpose drives a proposal with the runtime's own `author_graph` prompt; two host tools check it (`validate`, `explain`) without writing; a preview shows the exact graph bytes, the runtime's findings and plan, and the whole old and new `jpack.json` with its diff; one confirmation writes both. The write holds the project folder lock and runs through the guarded writer; `configVersion` never moves; a declared path that collides with a pack, a matrix, a rows file or another graph is refused, case-insensitively.
- **Rehearse a graph** (a graph's page → Rehearse). You supply facts, keyed by node id; Desk runs `graph evaluate --rehearsal` and shows the runtime's status, dispositions, nodes, feeds, traces and hand-offs with every label as the runtime printed them. Nothing is kept: no file, no record, no trail line, no log line. The page says what a rehearsal shows and what it does not, and that no digest joins it to the drawn document.
- **Runtime v0.28.0.** The audit report's sentences are held to the committed prefix and to direct evidence after a chain break; a stamps file over 64 MiB is refused rather than silently read in part; the companions are opened under the trail lock; `audit verify` can read a checkpoint witness's statements (Desk does not use the new flags yet).
- **Runner v0.7.0.** A trusted receipt key is held to the curve; `verify-run` holds a run's retained answer to its signed record (`audit-disposition-mismatch`).

## What a graph establishes, and what it does not

Unchanged from ADR-0011 and from v0.9.0: a graph's disposition in Desk is the runtime's experimental answer over the project's packs, shown as given. Desk makes no conformance claim for a graph; a rehearsal records nothing and the trail is silent about it, as runtime ADR-0048 says; Jobs executes no graph. An authored graph is the owner's file, written on the owner's word through the same guarded writer as every project file.

## Authoring through the assistant (#346, ADR-0011 row 3)

- Routes `POST /api/graphs/{validate,explain,proposal,write}` sit behind the same session and origin guard as the other state-changing routes. `runRuntimeInput` shares `runRuntime`'s environment, 20 s deadline and 64 KiB output bound and adds a 4 MiB standard input; the proposal reaches `graph validate -` and `explain -` on standard input only, never as a shell word.
- The confirmation is a MAC over the whole offer, the desk or project identity and a nonce: one pending offer per desk, replaced by a new preview, spent on use and on refusal, refused after `jpack.json` changed under it.
- The write holds the project folder lock and Desk's one write mutex and runs both commits through `commitWriteLocked` with `Override: false`: a creation writes the graph then the declaration, an edit writes only the declared graph; a declaration that fails after the graph was written is reported as such. The declaration is built span-preserving, so existing bytes and large numbers in `jpack.json` stay as they were.
- The assistant's host tools write nothing (the project tree's digest is unchanged after each); the pack-specific critic is skipped for a graph purpose; the review lock still binds the assistant (runtime ADR-0044 point 5).
- The review round's eight findings, all fixed before the merge: the proposal no longer holds Desk's write mutex while the runtime runs; the collision check looks through case and resolved paths; the edit-path guard and `hasLock` each hold a test, and a lock whose `Lstat` fails is a read error, not "no lock"; a read-only `jpack.json` refuses the proposal rather than leaving an undeclared graph; the page's words for a refused first commit and for the reviewed set hold to what exists; `runRuntime` keeps `/dev/null` as its input where a command reads nothing. A ninth, from the rows: the proposal's preflight refuses a listed path that climbs out through a symlinked folder, and a missing folder, with a test no later check masks.

## Rehearsal evaluation (#352, ADR-0011 row 4)

- `POST /api/graphs/evaluate?id=<configured id>` sits behind the same session and origin guard as the other state-changing routes. The id is resolved from a fresh `graph list` (row 1's rule); the body is the raw inputs object, bounded to 4 MiB before any runtime command, and reaches the runtime only on standard input (`--inputs -`); `--rehearsal` is always passed and `--cites` never; the existing 20 s and 64 KiB bounds and the path redaction apply, the error path included.
- A refusal (an answer that did not evaluate and carries diagnostics) is shown as "The runtime refused the rehearsal:" with each diagnostic's code and message, redacted of absolute paths but keeping the JSON pointers that name the owner's own inputs; an answer that evaluated without `rehearsal: true` is an error that says so; a failed run reaches the page redacted and the log not at all.
- Nothing is kept: the real-runtime test compares the whole project's bytes before and after a rehearsal over the configVersion-2 fixture, and a seeded configVersion-3 trail with three deciding records stays byte-identical.
- The result shows the runtime's status and labels, then the runtime's own members as a plain list under their own names (the headline disposition, each node's id and disposition, its feeds and trace where present, the hand-offs), each from the answer's original bytes, with the raw answer beside them; the page says, in ADR-0011 §9's words, what a rehearsal shows and what it does not, and that no digest joins it to the drawn document.
