# Private Dialect mapping and publication checks

The private Go host registry offers `read_dialect`, `propose_dialect`,
`read_dialect_publication` and `propose_dialect_publication`. Reads are fresh,
reference context available to Plan and delegated readers. Proposals are root
Work only. Production registration and the browser executor migration remain
pending; this foundation does not activate a replacement executor.

A mapping read binds the saved preparation revision and exact declared pack
bytes. It exposes bounded column samples, original field declarations and pack
requirements, without connection settings or source credentials. A proposal is
a complete replacement with explicit conversions and omissions. Runtime checks
the original mapping and pack; Desk's existing conversion service previews
records without evaluation or source acquisition. Research values use their
original recipe declarations, preserving missing values, false, zero, decimal
strings, lists and ranges. Incomplete diagnostics are retained truthfully.
Neither a check nor a preview saves a recipe or authorizes a decision.

Publication reads bind asserted/generated source identity and the selected
immutable base. The existing publication service receives a host-fixed `check`
admission, persisted time and request metadata. Model arguments cannot request
Publish, submit review receipts or claim an allowance. Runtime owns canonical
identity, compatibility and version decisions. The check can retain candidate,
recipe, pack and review evidence. Each owning mutation checks current authority
after its queue and before writing. Authority belongs to one invocation and
repository instance; unsupported injected owners refuse host admission. Manual
callers keep their default behavior. Exact completed publications reconcile as
observations before fresh validation; no new publication or job pin is made.

Each producer has a finite intent, exact prior root-read association and later
Runtime operation receipts. The shared journal retains its fixed action ID,
time, original model fields, report, preview and observed result. An uncertain
attempted publication-check retention records a typed unknown storage outcome
and stops automatic execution. Recovery inspects retained evidence; it never
reruns Runtime, the model or a write to manufacture a replacement receipt.

Terminal projection appends only these two finite action kinds to the existing
bounded `inputActions` array. It preserves unrelated raw actions and applied
state. Fresh writes recheck preparation, pack/publication base and physical
review dependencies; acknowledged exact chat bytes need no new feature effects.
A stale action can remain readable historical evidence while fresh projection
refuses. Generic run GET/SSE/list/Stop do not depend on current feature freshness.
No cross-file transaction or atomicity is claimed. Publication remains a
separate reviewed action through the existing approval dispatcher.

Focused fixtures cover actual API and native parent/child producers, finite
arguments and import custody, source changes, owner queues, uncertain retention,
completed reconciliation and existing browser action/check/review readers. The
standard projection CI command requires the named producer and exact reader
success. Record/activity/action tools, acquisition, grants, actual Publish,
production activation and the separate released-Runtime test proposal limitation
remain outside this slice.

Go mutation jobs supply a dedicated, explicitly configured Runtime fixture through
the existing attested companion owner. They do not export `JPACK_BIN` or enable
older Runtime-gated baseline tests. Missing or invalid explicit fixtures fail
setup; local focused checks may still supply an explicit `JPACK_BIN`.
