# Server test-design host tools

The finite shared host registry owns `read_pack_tests` and `propose_test_cases`.
A parent Work proposal requires a completed root read of the exact declared saved
pack or real unfinalized draft, suite presence, full case basis and optional
current coverage run. Plan and delegated children can read but cannot propose.
Runtime guidance, matrix contract and validation use the existing admitted Runtime
transport. Design runs no tests and saves no cases or project files.

Facts, authored expectations and source bytes remain unchanged. Runtime receives
all matrix fields except the two documented Desk metadata members,
`sourceMappings` and `intentionalFactTypes`. Validation requires complete ordered
row identities and fact checks. Wrong-type findings require explicit matching
explanations; source mappings refer only to supplied sources. Coverage proposals
use new case IDs. Browser `jsonIdentity` case snapshots preserve the existing
reviewed replacement/stale guard; they never replace exact journal custody.

A finite producer-bound output retains the exact ready proposal, before-read
basis and actual validation receipt before materialization. Under the existing
short private transaction, a new suite append requires current source/lifecycle,
suite presence and exact unchanged case bytes. It increments only suite revision
and proposals, retaining unrelated raw data. An existing identical ID and content
is readback recovery; contradictory IDs refuse. Completed historical proposals
remain observations if the pack later changes or finalizes. No recovery path
replays Runtime or a model. Already observed output survives cancellation/Stop
with bounded persistence, while authorization and producer work remain cancelable.

Every successful completed-call redelivery and terminal projection verifies or
materializes the suite record before exposing a review link. The existing chat
prepare/CAS/readback/ack path appends `turn.testDesign` only afterward. The two
files use ordered recoverable writes, not an atomic multi-file claim. Raw run
snapshots retain exact observed results even after a suite conflict; they alone
cannot establish a current review action. History and Stop stay readable. A thin
client must use verified host redelivery or final chat projection for ready review
controls, rather than treating raw operation results as current custody. Proposals
require separate human review and typed save authorization; the pure browser
review helper in fixtures never persists cases.

contract, including existing-case review and stale refusals. The peers implement
the existing Desk consumer contract by hand. **Pinned Runtime v0.37.0 accepts only

Selected gap-filling coverage is the exact retained run record, not just its ID or
pack/case validity. Required-read and Runtime dispatch rechecks compare that
selected record again; a new proposal append repeats the same check. Unrelated
runs and review-only proposal metadata stay outside this basis. Already retained
exact proposals remain historical observations when coverage later changes, with
no model or Runtime replay. Missing proposals cannot be recreated under changed
selected coverage.

on decoded string slices. Null and other nonstring members make live validation,
retained validation receipts and imports unavailable; authored wrong-type facts,
their explanations and expected outcomes remain unchanged.
