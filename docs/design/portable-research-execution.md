# Portable research in job preparation

A published research Dialect and its installation bindings remain separate. Desk
freezes the input prefix, Runner-resolved request, exact model connection revision,
profile definitions and initial allowance when the user prepares a review. A
review performs contract checks only. Starting it is a separate explicit action;
chat automation uses the shared scoped action-approval dispatcher.

The background worker uses the same durable research journal, attempt admission,
leases, request accounting, failure metadata, context projection, retained-section
retrieval and model executor as local research. Portable journals have version 2;
local recipe journals retain their version 1 representation. Provider credentials
stay in their existing custody. Each model response is a real Gateway acquisition
through Desk's private, single-use model adapter. Search/page operations use
reviewed generated profiles. Requests use singleton Gateway sessions; a prefix
that already relies on a shared session chain is refused before model spending.

The result is the Spec research response envelope, with original typed fields and
ordered acquired responses. Runner verifies each proposed result against the
frozen input before completion. Earlier model responses remain retained during
correction. Contract failures and repeated completed operations use a bounded
correction path; neither changes the definition, expectations or admission.
Uncertain operations are interrupted and never automatically replayed. A known
allowance refusal offers a persisted, bounded increase that requires approval.
Plan is checked again before dispatch, including after waiting for relay capacity.

The job form uses shared compact buttons, connection selection, progress, steps,
budget tables, notices and loading states. Installation binding changes never
modify an imported Dialect definition. Fixed job releases cannot be rebound;
changing those bindings requires an explicit job upgrade. The review displays
and locks its frozen connection and allowance.

Before execution is offered, a job draft records its research reference. Existing
jobs retain their form under `.desk/job-run-inputs/<job>/<release>.json`, through
normal optimistic file writes and read-back verification. These files contain
configuration and bounded run references, not acquisition receipts. Results and
attempts remain in private research journals. Reload reads the journal; it does
not restart work. Changing a selected file invalidates result reuse but preserves
access to the active run and its Stop control. Completed prefixes are reused
without reacquiring their dependencies; Runner checks them again before preview.

Validation includes real Runtime/Runner/Gateway execution on file and memory
journals, typed false preservation, correction, explicit model/page allowance
increases, cancellation, Plan changes, uncertain-operation recovery, immutable
history and large JSON escaping. Browser fixtures cover remount, explicit start,
changed-input refusal, frozen release controls, budget review and job form
reference persistence and delayed-save cancellation/navigation. Test providers and content are synthetic; these checks do
not establish live research accuracy.

Remaining delivery work: released-template tests across two installations and the
separate draft RFC0020 company-to-selected-company/person workflow executor and
verifier. This feature does not claim RFC0020 workflow conformance or publication
of the pending Exchange templates.

Page profiles currently pin one exact acquisition endpoint. A generated page
profile does not authorize arbitrary discovered URLs. General crawling needs a
coordinated Spec/Runner/Gateway contract; Desk must not erase or rewrite the
receipt endpoint to make it fit a profile.

A separate fresh-import acceptance fixture runs the same unbound definition on
two isolated Desk/Runner/Gateway installations, each with its own connection
revision, registered model profile and signing key. Both execute once and replay
twice without more model calls. Copying one installation's retained responses
into the other's input must produce Runner's explicit profile-mismatch refusal.
This test is required in companion CI; ordinary unit runs skip it when the pinned
companions are absent. It does not substitute for the pending signed Exchange
release or the two-stage workflow recording.

Local search registration uses the trusted Gateway adapter's versioned research
binding description. The review displays its endpoint and executable version;
explicit confirmation rechecks the same description before registering an
immutable Runner profile. The current connection revision and executable/key
identity participate in the profile ID. No provider URL or adapter version is
reconstructed by Desk. Registration performs no acquisition and spends no request
allowance.

Research freezes the current descriptor with its existing journal. The model
sees the declared request schema; the worker supplies the reviewed fixed
connection/revision and refuses a conflicting value before acquisition. Gateway
still enforces its own request, policy, revision and allowance checks. A changed
connection requires a new review; old profiles remain available for historical
verification. This local helper does not register profiles for external Gateways
or admit an arbitrary page endpoint.
