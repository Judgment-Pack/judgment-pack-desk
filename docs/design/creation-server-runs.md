# Generic creation server runs (#648)

NewPackView creates a real ChatStore conversation and displays ChatPanel. Only an
exact acknowledged terminal server projection can materialize its PackDraft and
navigate to DraftPackView. Observation alone never checkpoints or creates a draft.
DraftPackView uses the selected canonical chat, or displays the retained draft
through a pure historical binding while a current chat is selected. It never
constructs or restores the legacy browser execution owner.

## Admission and independent expectations

Each explicit creation control is a closed `creation` member on a real saved user
turn. The existing request/admission identity is persisted before POST. Send,
uncertain delivery, reconnect, Stop, session change and route detach retain the
saved-chat lifecycle; no action is replayed on refresh. The private executor reuses
the canonical compiler, managed context, adapters, Runtime tools and private ledger.
It is not installed as the global production factory by this slice.

Recover identifies an exact retained assistant message by its ID and text digest.
Legacy messages without IDs use the canonical stable `legacy-turn-N` identity.
Only one complete strict proposal is accepted; submitted prose, ambiguous fences,
truncation and malformed unknowns are refused. Recover and generic checks perform
model-free Runtime validation. Checks do not acquire sources or establish cases.

Establish cases is an explicit model admission with independent inputs: original
person statements, current verified citations and declared outcome/evidence/target
contracts. Draft rules, previous assistant answers and Runtime observations are
excluded. The full reviewer proposal is retained before finite expectation
validation. Retry validates that exact retained proposal without another reviewer.
Case IDs, order, typed facts, missing values, numeric tokens, expected disposition
and handoff target survive both valid and invalid findings.

## Source custody and correction

Current evidence requires the existing rooted document/Gateway proof and exact
attachment, digest, selected page, source URL and excerpt. Verification is checked
again before finite calls and inside the final projection transaction. Cached
cryptographic work never substitutes for current rooted bytes. Historical
`src-N#eN` rows and restored verification flags remain readable data; they cannot
establish expectations or authorize approval. An explicit research choice starts
a fresh read-only canonical request through the existing acquisition owner, under
current Plan, Ask me/Auto and compute controls, to obtain new current proof. It is
not a general acquisition or write grant and never silently replays earlier work.

Correction starts from a current unresolved typed validation finding. The
independent reviewer receives original grounds and the fixed original target,
without draft rules or observed decisions. A visible proposal token binds the
replacement, original case, target, candidate bytes, source/case evidence,
generation, authenticated session, project and chat. A later explicit person action
must match that token and its retained completed proposal witness.

Approval stages the replacement, revalidates expectations and retests the full
unchanged suite against the exact unchanged candidate. Duplicate established IDs,
shortened reports and changed targets are refused. Only successful full retest and
current-source projection CAS publish the replacement and resolve the issue.
Interrupted or failed retest leaves the original issue unresolved; completed
operations and staged data remain retained without replay authority.

## Readiness and manual creation

The public optional `creation` projection contains bounded cases, held proposal,
typed issues, current check and visible correction proposal. Browser readers
require exact current candidate and case/issue/held data before overlay. Historical
checks remain display-only and restored tokens are never approval authority.
Current readiness also binds generation, documents, sources, interaction phase,
connection/model and original current chat grounds.

Finalize remains a separate reviewed manual write. It awaits a fresh current host
check and then rechecks the local candidate, dirty/loading/saving state, generation
and detach guard immediately before physical writes. Existing DraftPersistence,
three-way merge, raw JSON provenance and CAS preserve local edits and source rows.
Derived draft links, successful checks and research Auto do not authorize writes.
Reviewed typed cases and source handoff data are carried unchanged into creation.

Runtime 0.37's supported creation suite remains in use. The explicit unsupported
fact-check proposal guards for #582 remain pending Runtime 0.38; no component pin,
unsupported acceptance path, route or main-chat layout changes are part of #648.

## Evidence

Handwritten tests cover current/stale source, candidate, case, token, target,
generation and session scope; missing/zero/false/null facts; full-suite retest;
interruption rollback; historical proof refusal; and write/detach vetoes.
`assistant-creation-readers` runs actual authenticated Go API and native producers,
including stopped validation/retest, then feeds their temporary observations to
the strict browser snapshot/SSE/creation readers and mounted NewPackView/
DraftPackView journey. These observations are not recorded golden vectors.
Final activation, complete CI and independent review remain coordinator gates.
