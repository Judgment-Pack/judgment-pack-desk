# Canonical memory proposal acceptance

This bounded candidate consumes released Agent v0.9.1 `remember {kind,text}`, memory events and checkpoint proposals. Agent owns proposal identity, kind, text digest, source run, count/byte limits, Plan classification and child/critic/reformatting refusal. Desk owns current settings, private recall, person review and storage. No second tool, protocol, store or provider loop is introduced, and the global execution factory remains inactive.

Suggest and Use are separate. A saved-chat admission retains the current Suggest boolean in its host source binding. Suggest-off supplies `PolicyProject.budget.memoryProposalsPerRun = 0`; enabled admissions inherit the released table. Existing current-source authorization runs before every canonical tool and provider dispatch and refuses if Suggest changes. Resume cannot silently replace an admitted budget. A new response is required. Use changes continue through the typed recall/lifecycle boundary and do not alter proposal authority. Turning Suggest off retains existing proposals for explicit person review. Host-authored independent creation review actions (`establish-cases`, `propose-correction`) capture proposal authority as false and receive the same canonical zero cap even when Suggest is enabled. Their current saved action independently refuses acceptance. Non-chat purposes cannot supply the required saved human-turn attribution.

The existing memory GET returns optional `proposals` alongside the private document. Each projected row has the retained `runId`, `runRevision`, host-derived `chatId`/`turnId`, exact canonical `memory` and a `reviewable` flag. It is an observation of retained checkpoint data, never a pending-entry write. Only current-session, nonhistorical saved-chat proposals can be reviewed; the run must be paused or terminal, and the latest saved user turn must still match its pinned request. Appended terminal assistant output does not invalidate the user-turn attribution. A new user turn does. Stale sources disable review; Clear hides excluded old pending proposals.

A person submits the existing `/api/ai-memory` POST with action `review` and one closed review object: delivery `id`, `runId`, `runRevision`, `proposalId`, `proposalDigest`, `decision` (`accept`, `decline`, `edit`) and `text` only for edit. If-Match binds the reviewed private-store revision. Source IDs, paths, topic keys, canonical records and actor fields are not request inputs. The server rechecks current authenticated principal/session/policy, project namespace, exact retained run/proposal/revision, latest saved turn, source digest, tombstones, Clear cutoff, verified dependencies and existing sensitive-text/count/byte limits before writing.

Topic keys are `canonical-<kind>-<normalized kind/content hash prefix>`, derived by the host. A verified retained saved-pack read contributes its exact path/digest dependency; no dependency is guessed from prose or supplied by the model. Without such a read, a stable textual preference has no file dependency. Changed/unavailable/symlinked dependencies refuse acceptance. The latest saved user turn supplies chat/turn attribution and the existing source tombstone hash; old prose saying remember cannot accept a canonical proposal.

Accept retains the canonical proposal's exact ID, digest, source, kind, text, creation time and expiry. Edit preserves kind/expiry but uses exact person-edited text and a distinct project/person/intent/content-bound identity, source and digest. Decline records only the decision for this proposal and never stores its text. A canonical proposal remains unchanged in the Agent checkpoint; the private owner supplies acceptance and typed recall separately.

The private version-1 document adds optional `reviews`, bounded to 512 metadata-only receipts. A receipt records delivery/intent digest, authenticated opaque principal/session/policy/project, reviewed run/revision and proposal ID/digest, decision/time, and accepted entry/canonical ID/digest when applicable. The entry and receipt commit together through the existing atomic replacement/readback under the shared private-data lock. There is no independent external write to replay. A known completed delivery with the exact owned intent can return its retained result even after Forget/Clear, without creating an entry. Another delivery for the same proposal conflicts. Missing/unknown outcomes never cause automatic retries; browser errors refetch observations. GET, reload, Stop and checkpoint restoration never accept proposals.

Receipts survive Forget/Clear and roundtrip through strict private/backup readers. Unknown/null/missing/malformed receipt fields, duplicate deliveries/proposals and invalid result links refuse. The browser uses the released Memory reader for canonical schema/digest validation, matches review acknowledgements to the exact submitted intent, and freezes proposal/store revisions while editing. It registers manual edits and pending writes with the shared unsaved-state registry. Actual canonical observations refresh the existing private query rather than polling or dispatching model work. Receipt/projection metadata is never concatenated into recalled text.

Handwritten shared vectors cover all receipt members and decisions in Go/private-backup and browser readers. Actual API/native Work/Plan probes cover Suggest on/off, person accept/edit, typed recall and Clear/forget receipt reconciliation. Actual independent creation reviews attempt reserved remember, retain its canonical limit refusal and complete with readable checkpoints and no proposal; person acceptance remains refused. Additional probes cover source/session/revision refusals, concurrent CAS, uncertain readback, live/paused settings authority and observational browser recovery. Exact-head CI, independent review and maintainer integration still gate the candidate.
