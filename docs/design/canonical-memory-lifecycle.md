# Canonical private memory lifecycle

Desk's private memory remains a version-1 document in the existing project history namespace. An entry may retain a closed optional `canonical` object with `id`, `kind`, `source`, `digest` and optional `expiresAt`. The source has `run` and `proposedBy`. These fields describe the original canonical proposal; they cannot authorize its acceptance. Existing management state determines whether recall is allowed, and existing `createdAt` supplies canonical creation time. Scope is always project. No new endpoint accepts proposal metadata and no proposal is automatically accepted.

Enriched entries project exact text and metadata through released Agent `contract.Memory`, `ContextDigest` and `RecallMemory`. Legacy entries project a deterministic project/version-bound host reference, with the topic prefix preserved. An edit discards canonical metadata and projects a new host version. Private reads and backup validation reject malformed or duplicate canonical identities, mismatched content digests, unknown members and explicit null metadata/expiry. Valid legacy records are read without adding metadata or writing a migration.

The host answers the released `MemoryLifecycle` callback even when prompt memory is disabled. It reads the existing store under the shared private-data lock and checks current dependencies. It compares retained accepted identity/digest/kind against the entire current eligible set before query ranking and the five-record/4,000 canonical byte projection. Missing, inactive, changed, disabled or dependency-invalid versions report `revoked`; eligible expired versions report `expired`. Terminal records receive no new transition. Relevance omission does not report a terminal transition. Prior metadata is never a source of text or a new canonical identity.

Lifecycle and recall share one immutable private store/dependency snapshot for each execution prompt host, including concurrent delegated-child callbacks. Each resumed execution opens a fresh host. Agent retains the recalled data for the run, so concurrent management changes affect the next run or resume. Revision checks continue to serialize competing writes; readers never repair or overwrite the document. Backup, project move, sensitive-content refusal, tombstones and the Clear generation barrier retain their existing paths. Canonical metadata is omitted from legacy recalled entry JSON and is never concatenated into entry text.

The regression probes cover the actual authenticated API and native bindings, person-question pause/answer continuation, checkpoint reload, disabled recall, dependency changes, expiry, forget/clear/edit, immutable live recall, query omission, concurrent CAS, project isolation and canonical byte bounds. The released request/phase and Desk admission guards still precede resumed host assembly. A changed retained request is refused and requires a new response; lifecycle does not bypass that refusal.

Human proposal acceptance and its receipts belong to #598. Global execution factory activation, background execution and deletion of old engines remain separate work. This change adds no remember tool, provider loop, automatic acceptance, permission, evidence or expected-outcome authority.
