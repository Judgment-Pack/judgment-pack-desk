# Private Dialect recipe host foundation

The ordinary private assistant factory offers exactly four recipe capabilities:
`get_dialect_recipe_instructions`, `list_dialects`, `read_dialect_recipe` and
`propose_dialect_recipe`. The first three are read-only and child/Plan eligible.
Only the static instruction contract is immutable. Lists and recipe reads use
current preparation storage and return portable design data, never records,
AI/search bindings, credentials or embedded qualification packs.

A root Work proposal retains the model's original generic fields, descriptions,
criteria, structured limits and optional execution policy. Modern and historical
field types stay distinct. Blankness uses the existing browser whitespace
predicate; original strings are never trimmed or normalized. The host fixes the new recipe target to records;
metadata, connection choices and source requests cannot come from model fields.
The independent review draft uses the existing browser recipe defaults: search
budget zero, empty AI binding and the normal temporary retry default. The proposal
card retains the original requested limits for human setup. No preparation or
research job is created.

Before create, the existing host-operation intent stores the exact candidate,
deterministic originating draft identity, creation time, current turn and model
attribution in one finite `recipeProposal`. Unrelated intents refuse that member.
The producer uses the existing create-only draft service and verifies its actual
readback before atomically retaining the tool result and finite domain output.
No second journal, arbitrary JSON operation or new HTTP dispatch is introduced.
An attempted create/readback with an unknown outcome retains a typed storage
failure with outcome unknown, then stops the execution. Known pre-create storage
and capacity refusals are not-started. Redelivery never calls ensure, a model or
another effect. Run/history inspection and Stop remain available. Recovery inspects the original receipts.

Conversation writes, the existing draft workflow lease and short repository
transactions preserve their lock order. Current authorization is checked after
queueing and immediately before file writes without reentering private storage.
The completed draft exists independently of chat. Terminal projection checks its
exact retained snapshot under the workflow lease through conversation readback.
Manual edits, discard, Save to Dialects or physical deletion make a still-pending
projection refuse; they never overwrite/resurrect the draft or erase/reclassify
the completed producer. The historical output remains available for later thin
client reconciliation. An already projected chat can recover acknowledgement by
readback alone.

The standard projection check runs the actual API producer into fresh files,
requires its named PASS, then consumes both saved chat and retained draft through
existing browser readers. Native fixtures also cover parent-child-parent callbacks
with repeated provider IDs. Dedicated tests hold typed fields, current authority,
Plan/child refusal, exact metadata/import binding, capacity and lost-ack behavior.

This remains an unregistered private foundation. Existing browser execution is
unchanged. Record/activity/action capabilities,
separately approved research starts, background/action/CAS migration and full
production cutover remain pending. Runtime test-proposal compatibility under
Desk #582 is separate from this four-tool recipe slice.

Current-authorized draft storage is bound by the owning draft repository. Host
features use logical draft identities through that contract; they never open
draft directories or construct file adapters. The owner binds authorization
after queued file locks and before writes, and fences injected adapter results
with the same current-authority checks. Ordinary repository callers keep their
existing binding and create-only behavior.

Private mapping/publication checks are described in [their host foundation](assistant-dialect-mapping-host.md). They do not activate production or actual publication.
