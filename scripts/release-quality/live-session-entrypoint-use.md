# Live session entrypoint preparation

Importing `live-session-entrypoint.mjs` does nothing; running it prints a disabled manifest. There is deliberately no execution flag. No live access has been qualified by the handwritten doubles.

A later separately approved local orchestrator may import `runLiveSession(options, operator)`. Approval of sign-in, exact model/effort, bounds, subscription monetary basis and execution must already exist outside this function. Readiness callbacks and saved decision digests do not grant approval. Do not invoke this function until the concrete binaries, source/accounting/helper overlays, assets, corpus and capture reader have been independently qualified. Each role needs its own fresh private project/config/control/evidence directories; the real Go owner checks their freshness. Supply absolute owner/browser/native/Runtime/assets paths, explicit startup/setup/cleanup milliseconds, and the exact `live-two-chat-capture-input` control accepted by the shared capture. No model is chosen or substituted. Baseline requires its explicit reader path and SHA; retain its original source identity and accounting/helper overlays separately.

`operator.verifyCustody({options,signal})` must verify exact source inventory, assets and fixed public corpus/slice hashes against the separately qualified metadata, including the CLI version and role overlays; return true only on agreement. The launcher additionally hashes supplied executables, shared capture and role reader. A Runtime executable wrapper, if separately approved, must have its own exact `source.runtimeInput` executable hash; keep the underlying recorded result/peer identity in custody evidence. Never label supplied recorded Runtime input as actual Runtime execution.

`operator.setupUI({page,origin,setupToken,connectionName,model,effort,signal})` uses the same normal browser page that capture will retain. At the initial Desk page, choose Set up sign-in, enter the ephemeral Owner setup code, Continue, then have the operator complete normal Set password and Sign in. Open `/admin#connections-ai`, Add connection, choose Provider = ChatGPT subscription, use the supplied connection name and Add connection, then Manage. Choose Sign-in method = Device code and Connect ChatGPT. The operator completes the displayed normal challenge privately. Do not press Test connection. Save the explicit model, effort and get_schema-only shared settings through normal UI. Return only `{connectionId}` for that saved named connection; do not return tokens, URLs, codes, cookies or profile data.

`operator.verifyReady({page,control,signal})` must independently read back the normal named connection, connected account, exact offered model/effort and allowed get_schema tool settings, with no extra inference. Return true only after the separately approved setup is complete. Capture then configures and verifies the normal per-chat task/provided/draft/Work/critic-off settings, preserves raw baseline omissions and uses two distinct fresh chats in this same context. The application owner holds its one private profile and accounting sink, preserving sequences 1 and 2. Setup failure or timeout closes the session and skips capture.

These callbacks must honor AbortSignal, use bounded waits, and never log arguments, caught error prose, DOM/network dumps, screenshots or challenge payloads. Passwords and device challenges remain ephemeral in the operator UI. This host has not established a visible desktop or another usable operator interaction surface; headed Chrome alone does not establish one. A later orchestrator must supply a private interactive operator surface and these callbacks before a live invocation is concrete. No browser session export, registry injection, terminal-auth reuse or credential copying is supported.

Startup, setup and cleanup have separately supplied bounds. The existing owner enforces 120 seconds per case and 480 seconds aggregate inference, and capture has a 600-second outer watchdog covering its readiness plus inference. These are wall-clock controls, not hard token/currency ceilings or prospective one-invocation/callback caps. On failure the launcher requests real owner abort and awaits its exit and normal Server shutdown/reap evidence before closing the retained browser. If cleanup evidence is missing it reports incomplete; it never kills a native wrapper to claim reap. Preserve the returned incomplete status privately, along with the existing capture artifacts; output no raw setup exceptions. No artifact destination is inferred by the launcher.

Successful capture retains full ordered saved/rendered/reloaded answers and private canonical references through the existing capture retainers. Usage scopes/missingness and unproven finality remain intact; subscription monetary cost is unavailable (`null`). Completion does not accept answer changes: the answer-change decision remains pending. This entrypoint is preparation only and does not execute the closed comparison plan or automate release acceptance.

## Prepared normal UI callbacks

`createLiveSessionOperator({role, humanOwnerSetup, humanDeviceSignIn})` from `live-session-operator.mjs` now supplies the concrete `setupUI` and `verifyReady` callbacks. Use the exact baseline/candidate role and merge these callbacks with the separately supplied `verifyCustody` for `runLiveSession`. The factory and import perform no account or UI work. Prior operational approval remains an external prerequisite; invoking a human callback does not create approval.

Supply two private interactive handoffs. `humanOwnerSetup({page, origin, setupToken, signal})` must let the operator complete normal setup-code/password/sign-in in that supplied page and return void or true only. `humanDeviceSignIn({page, signal})` must let the operator complete the normal challenge already displayed by Connect ChatGPT in that same page, returning void or true only. Neither callback returns a password, URL, code or credential. Both must honor AbortSignal, cancel their operator interaction on abort and avoid logs/screenshots/session exports. This host still needs a usable private operator interaction surface; DISPLAY or headed mode is not proof of one.

The implementation waits for normal authenticated UI and verifies a nonempty browser session subject, creates the fresh named subscription connection through UI, explicitly selects Device code, and never clicks Test connection. Fresh registry must be empty; unrelated or preexisting connections refuse. The new connection auto-opens its editor in both source versions. It selects exactly the requested model/default/effort and get_schema-only tools through UI. `verifyReady` reads the saved registry plus selected named account status/model catalog using normal authenticated GET requests and X-Assistant-Connection, with the bearer held only in memory. Exact name/id/default/enabled/provider/model/allowed-models/effort/tools and account/runtime/catalog offers must agree. Candidate optional accountRevision is checked if present; baseline omission is preserved. Candidate-only review/helper defaults are not injected into baseline.

A connected account and offered model/effort establish setup readiness only. Actual model-access success is established only by the first authorized application inference, which may still refuse. The callback closes only its supplied page on abort to interrupt pending UI auto-waits and checks the signal before/after every action/read; it starts no later Connect/save/readback after observed abort. Already dispatched application writes cannot be retracted. Real owner abort/Server cleanup/reap stays with the entrypoint. No actual sign-in, browser mount or model access has been qualified by these handwritten tests.
